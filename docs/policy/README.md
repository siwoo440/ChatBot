# 개인정보처리방침과 이용약관 초안 안내

이 폴더에는 Mate Verse를 다른 사람에게 열기 전에 필요한 두 문서의 초안이 있다.

| 문서 | 내용 |
| --- | --- |
| `privacy-policy.md` | 개인정보처리방침 초안 |
| `terms-of-service.md` | 이용약관 초안 |

## 1. 지금 상태

- **초안이다.** 아직 시행하지 않았고 앱 화면에도 붙이지 않았다. 앱의 `개인정보 및 보안` 화면은 여전히 "운영 정책이 확정된 뒤 게시된다"고 안내한다.
- **법률 전문가의 검토를 거치지 않았다.** AI가 앱의 실제 동작을 코드에서 확인해 쓴 글이다. 다른 사람에게 열기 전에 4절의 항목을 전문가와 확인하기를 권한다.
- 작성 기준일은 2026-10-08, 기준 코드는 커밋 `0d9281c`다.
- 문서 안의 `〔 〕`는 운영자가 정해야 채울 수 있는 곳이다(2절).
- 「지금」은 작성 기준일의 실제 동작, 「공개할 때」는 아직 연결하지 않은 것을 뜻한다.

## 3. 문서와 실제 동작을 맞춰 본 곳

방침에 적은 내용이 실제와 다르면 그 자체가 문제가 된다. 아래 기능을 바꾸면 방침도 함께 고친다.

| 방침의 내용 | 실제 동작이 있는 곳 | 확인한 것 |
| --- | --- | --- |
| 이메일 가입·로그인, Google 로그인에서 받는 항목 | `src/lib/account/supabase-account.ts` | 이메일, 비밀번호, Google이 준 이름을 읽는다. 프로필 사진 주소는 앱이 쓰지 않지만 Supabase에 저장된다 |
| 서버에 보관하는 계정 데이터 | `supabase/account-setup.sql`의 `mv_snapshots`, `src/lib/account/account-sync.ts` | 앱 상태를 통째로 한 벌 저장한다. 항목은 `src/features/core/types.ts`의 `AppState` |
| 자기 데이터만 읽고 쓰기 | `supabase/account-setup.sql`의 권한 규칙 | 시험용 데이터베이스와 실제 프로젝트의 읽기 요청으로 확인(`HANDOFF.md` 39절) |
| 탈퇴하면 바로 지움 | `mv_delete_account` 함수, `src/features/settings/AccountManagement.tsx` | 계정을 지우면 저장본도 함께 지워진다. 실제 프로젝트에서는 아직 돌려 보지 않음 |
| 데이터 내려받기 | `src/features/settings/DataManagement.tsx` | JSON 내보내기 |
| 생년월일을 저장하지 않음 | `src/features/adult/AdultVerificationDialog.tsx` | 확인 뒤 입력값을 비우고 결과(방식, 시각, 만료)만 저장 |
| 문의를 서버로 보내지 않음 | `src/features/support/SupportScreen.tsx` | 문의 글과 진단 정보를 복사만 한다 |
| 실제 AI로 넘어가는 내용, 서버에 저장하지 않음 | `src/lib/llm/prompt-builder.ts`, `src/app/api/chat/` | 요청을 AI 회사로 전달하고 기록을 남기지 않는다. 요청 수 제한은 접속 주소를 쓰지 않는다. 공개했을 때는 로그인한 사람의 계정 구분값별 횟수를 서버 메모리에서만 세고 저장하지 않는다(`src/lib/llm/chat-gate.ts`. 함께 쓰는 저장소로 옮기면 방침의 표를 고친다) |
| 쿠키와 분석 도구를 쓰지 않음 | 코드 전체 | 쿠키를 쓰는 코드와 분석 도구가 없다 |
| 브라우저에 저장하는 것 | `mateverse:v1:`로 시작하는 저장 칸(`src/lib/account/scoped-storage.ts`) | 앱 데이터, 백업, 임시 저장, 로그인 상태, 맞춘 기록, 이용 시간, 정렬과 필터 |
| 대화 화면의 AI 안내 | `src/features/chat/ChatScreen.tsx` | "AI가 만든 허구의 대화입니다"를 대화 화면에 표시 |

방침에 적었지만 **지금 구현이 약한 것**도 있다. 공개하기 전에 실제를 방침에 맞추거나 방침을 고친다.

- **금지 내용 검사**는 지금 낱말로 거르는 연습용이다(`docs/SERVICES.md` 3절).
- **성인 확인**은 생년월일 입력뿐이라 누구나 통과할 수 있다.
- **토큰 잔액**을 브라우저가 정한 값 그대로 서버에 저장한다. 토큰을 팔기 전에 서버가 정하도록 바꿔야 한다.
- **이용 제한(정지, 계정 삭제)을 하는 관리 도구**가 없다. 지금은 Supabase 화면에서 계정을 직접 지워야 한다.
- **공개 캐릭터와 신고**는 지금 이 브라우저 안에서만 동작한다(다른 이용자에게 보이지 않고, 신고도 서버로 가지 않는다).

## 4. 법률 검토 때 확인할 것

- **개인정보 보호법**: 처리방침에 꼭 적어야 하는 항목이 빠지지 않았는지, 수집·이용 동의를 어떻게 받을지(가입 화면의 동의 칸), 국외에 있는 회사에 맡기는 것을 방침 공개만으로 할 수 있는지.
- **Supabase**: 계약 상대 회사의 정확한 이름과 나라, 프로젝트의 보관 지역이 서울인지(Supabase 화면의 `Project Settings → General`), 지운 데이터가 백업에 남는 기간.
- **AI 회사**: 보낸 대화를 얼마나 보관하고 학습에 쓰는지(회사와 요금제마다 다르다. 연결하기 전에 각 회사의 약관에서 확인해 방침 6절의 표를 채운다).
- **인공지능 관련 법령**: 생성형 AI 서비스라는 사실을 알리는 방법과 AI 생성물 표시가 지금 화면의 안내로 충분한지.
- **청소년 보호**: 19+ 내용의 표시와 성인 확인 방법, 청소년 보호책임자를 두어야 하는 규모인지.
- **금지 내용**: 아동·청소년으로 보이는 인물의 성적 표현, 실제 인물의 성적 합성물에 대한 신고·삭제 의무.
- **약관**: 이용자에게 불리한 조항(책임 제한, 이용 제한, 약관 변경 동의 간주)이 약관 규제 법령에 어긋나지 않는지.
- **유료화할 때**: 전자상거래와 콘텐츠 관련 법령의 청약 철회·환불, 미성년자 결제, 사업자 정보 표시, 통신판매업 신고(약관 14조).
- **해외 이용자를 받을 때**: 나라마다의 법(유럽의 개인정보 규정, 미국의 아동 보호 규정 등)은 이 초안에 넣지 않았다.

## 5. 앱에 붙일 때 할 일 (다음 묶음)

2절의 1~4번이 정해지면 진행한다.

1. 방침과 약관 페이지를 앱에 만든다(예: `/policy/privacy`, `/policy/terms`). 시행 전에는 "운영 전 검토용 초안"이라고 표시한다.
2. 가입 화면에 동의 칸을 넣는다(필수: 이용약관, 개인정보 수집과 이용, 나이 확인). 동의하지 않으면 가입 단추가 눌리지 않게 한다.
3. 링크를 건다: 로그인 화면, `개인정보 및 보안` 화면, Text-Play 화면의 "준비 중" 표시 자리.
4. 영어 화면용 번역을 넣고, 영어 화면 전체 점검 테스트의 주소 목록에 두 페이지를 더한다.
5. 동의한 약관의 판(시행일)을 계정에 기록할지 정한다(약관을 고쳤을 때 다시 동의를 받으려면 필요).

## 6. 이 문서를 고칠 때

- 3절의 기능을 바꾸거나 외부 서비스를 새로 연결하면, 같은 커밋에서 방침의 해당 절을 고친다(`docs/SERVICES.md`도 함께).
- 시행한 뒤에 고칠 때는 문서 아래에 고친 날, 시행일, 바뀐 내용을 적고, 방침 13절과 약관 3조의 알림 기간을 지킨다.
- 초안 상태에서는 맨 위의 작성 기준일과 기준 커밋을 함께 고친다.
