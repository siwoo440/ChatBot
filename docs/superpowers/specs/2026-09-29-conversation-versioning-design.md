# 대화 메시지 버전 관리 설계

작성일: 2026-09-29
상태: 사용자 검토 대기

---
## 1. 목적

사용자가 과거 사용자 메시지를 수정할 때 기존 대화를 덮어쓰거나 제거하지 않고, 수정 지점부터 새로운 대화 버전을 생성한다. 사용자는 수정된 메시지 아래의 작은 전환 버튼으로 원본과 수정 버전을 오갈 수 있어야 한다.

성공 기준은 다음과 같다.

- 기존 대화와 모든 수정 버전 보존
- 버전별 메시지와 관계 상태 독립 유지
- 생성 실패나 저장 실패 시 원본 무변경
- 새로고침, 내보내기, 가져오기 이후 선택 버전 복원
- 데스크톱, 모바일, 키보드 환경에서 동일한 기능 제공

---
## 2. 범위

이번 개발 범위는 메시지 복사·수정·삭제, 버전 생성·전환·삭제, 로컬 저장 마이그레이션, 보관함·내보내기 연동이다.

다음 항목은 제외한다.

- 버전 이름 변경
- 버전 병합
- 전체 분기 트리 시각화
- 서버 동기화와 다중 사용자 공유
- 여러 기기 사이의 자동 동기화

---
## 3. 채택 구조

---
### 3.1 버전별 스냅샷

각 대화는 하나의 `Conversation`으로 유지하고, 실제 진행 상태는 `ConversationVersion`에 저장한다. 새 버전은 분기 지점 이전의 메시지와 관계 상태를 복제한 독립 스냅샷이다.

이 방식은 메시지 일부를 중복 저장하지만 다음 이점을 제공한다.

- 다른 버전을 변경하지 않는 단순한 수정·삭제
- 생성 실패 시 신규 스냅샷을 버리는 원자적 복구
- 참조 개수나 공유 메시지 정리 규칙 불필요
- 최대 10개 제한으로 로컬 저장 증가량 통제

---
### 3.2 대안 제외 근거

메시지 노드를 버전 사이에서 공유하는 트리 구조는 저장량을 줄이지만 삭제와 복구 시 참조 관리가 복잡하다. 버전마다 `Conversation`을 복제하는 방식은 기존 구조를 재사용할 수 있지만 보관함, 통계, 최근 대화 목록에서 중복 대화가 노출된다.

---
## 4. 데이터 모델

---
### 4.1 Conversation

`Conversation`은 다음 공통 정보만 소유한다.

- 대화 식별자
- 캐릭터와 사용자 식별자
- 제목과 시작 설정
- 보관 상태
- 생성 시각과 최근 활동 시각
- 현재 선택 버전 식별자

관계 수치, 관계 단계, 감정, 장면, 최근 메시지는 버전별 값으로 이동한다.

---
### 4.2 ConversationVersion

새 구조는 다음 정보를 가진다.

- 버전 식별자
- 소속 대화 식별자
- 부모 버전 식별자
- 분기 원본 메시지 식별자
- 같은 분기 지점의 표시 순서
- 관계 수치와 관계 단계
- 현재 감정과 장면
- 최근 메시지
- 생성 시각과 수정 시각

원본 버전은 부모 버전과 분기 원본 메시지가 없다. 수정 버전은 수정 당시 선택된 버전을 부모로 기록한다.

---
### 4.3 Message

`Message`에 버전 식별자를 추가한다. 버전 생성 시 분기 지점 이전 메시지는 새 식별자로 복제하고, 수정 대상 메시지는 새 내용으로 생성하며, 성공한 AI 답변을 마지막에 추가한다.

복제 메시지는 진단과 내보내기를 위해 원본 메시지 식별자를 선택적으로 기록한다. 화면과 대화 생성 로직은 현재 버전의 메시지만 조회한다.

---
### 4.4 저장 스키마

애플리케이션 저장 스키마를 6에서 7로 올린다. 마이그레이션은 기존 대화마다 원본 버전 하나를 만들고 연결 메시지에 해당 버전 식별자를 지정한다.

마이그레이션 실패 시 기존 저장값을 삭제하지 않는다. 현재 복구 사본 정책을 유지하고 초기 상태로 자동 덮어쓰지 않는다.

---
## 5. 사용자 메시지 수정 흐름

1. 사용자가 사용자 메시지의 메뉴에서 수정을 선택한다.
2. 메시지 위치에 인라인 입력창을 표시한다.
3. 공백, 원문과 같은 값, 입력 길이 초과를 거부한다.
4. 같은 분기 지점에 버전이 10개면 생성을 거부한다.
5. 토큰 1개 사용 가능 여부를 검사한다.
6. 분기 지점 이전 문맥과 수정된 메시지로 AI 답변을 생성한다.
7. 생성 성공 후 하나의 상태 변경에서 버전, 메시지, 관계 상태를 저장하고 토큰 1개를 차감한다.
8. 새 버전을 현재 버전으로 선택하고 주소를 갱신한다.

AI 생성 실패, 중단, 저장 실패 시 신규 버전과 토큰 변경은 없다. 원본과 현재 선택 상태도 유지한다.

---
## 6. 반복 수정과 분기

수정은 항상 현재 보고 있는 버전을 기준으로 새 하위 버전을 만든다. 기존 버전은 덮어쓰지 않는다.

같은 메시지 위치에서 생성된 원본과 수정본은 하나의 전환 그룹으로 표시한다. 수정 버전 안의 더 이전 메시지를 다시 수정하면 해당 위치에 새로운 전환 그룹이 생긴다. 내부 데이터는 부모·자식 관계를 유지하지만 MVP 화면에서는 전체 트리를 표시하지 않는다.

같은 분기 지점의 버전 수는 최대 10개다. 제한 도달 시 기존 버전을 자동 삭제하지 않고 명확한 안내를 표시한다.

---
## 7. 버전 전환 UI

버전이 둘 이상인 메시지 아래에 `‹ 1 / 2 ›` 형태의 전환기를 표시한다. 왼쪽과 오른쪽 버튼은 이전·다음 버전을 선택하며 가운데에는 현재 순서와 전체 개수를 표시한다.

- 시각적 크기는 메시지 보조 동작 수준으로 축소
- 실제 터치 영역은 최소 44×44픽셀
- 이전 버튼 접근성 이름: `이전 대화 버전`
- 다음 버튼 접근성 이름: `다음 대화 버전`
- 현재 위치 접근성 설명: `대화 버전 1/2`
- 버전이 하나면 전환기 미표시
- 스트리밍 중 전환·수정·삭제 비활성화

버전을 바꾸면 메시지 목록, 관계도, 관계 단계, 감정, 장면을 함께 전환한다. 포커스는 누른 전환 버튼의 대응 버튼에 유지한다.

---
## 8. 메시지 동작

---
### 8.1 복사

사용자와 AI 메시지 모두 복사할 수 있다. 클립보드 성공 상태를 알리고 실패 시 데이터를 변경하지 않은 채 오류를 표시한다.

---
### 8.2 삭제

메시지 삭제는 현재 버전에만 적용한다. 사용자 메시지를 삭제하면 해당 메시지와 이후 메시지를 현재 버전에서 제거한다. AI 메시지는 선택한 응답만 제거한다.

다른 버전의 메시지와 상태는 변경하지 않는다. 삭제 전 현재 상태의 로컬 백업을 생성한다. 마지막 AI 답변이 삭제되어 사용자 메시지로 끝나면 다시 생성 동작을 제공한다.

메시지 삭제는 이미 사용한 토큰과 반영된 관계 수치를 되돌리지 않는다.

---
### 8.3 버전 삭제

원본 버전은 삭제할 수 없다. 수정 버전은 현재 선택 상태에서 삭제할 수 있다. 해당 버전을 부모로 사용하는 하위 버전도 함께 제거하며 확인창에 삭제될 버전과 메시지 수를 표시한다.

삭제 뒤에는 가장 가까운 부모 버전을 선택한다. 삭제 전 로컬 백업을 생성한다.

---
## 9. 상태와 토큰 정책

새 버전은 분기 시점의 관계 수치, 관계 단계, 감정과 장면을 복제한 뒤 독립적으로 변화한다. 한 버전의 이후 대화는 다른 버전의 상태에 영향을 주지 않는다.

토큰 지갑은 사용자 전체에서 공유한다. 버전 생성은 AI 답변 생성 성공 시 채팅 토큰 1개를 사용한다. 실패와 사용자 중단에는 토큰을 차감하지 않는다.

장기 기억 기능이 연결된 뒤에는 버전 식별자를 기억 출처에 포함한다. 특정 버전의 메시지 삭제는 그 버전의 자동 생성 기억만 정리하며 사용자가 직접 편집한 기억은 자동 삭제하지 않는다.

---
## 10. 주소와 선택 상태

채팅 주소는 다음 형식을 사용한다.

`/chat/{characterId}?conversation={conversationId}&version={versionId}`

주소의 대화와 버전이 유효하면 해당 버전을 선택한다. 버전이 없거나 삭제된 경우 대화의 마지막 선택 버전으로 이동하며, 그것도 없으면 원본 버전을 선택한다. 다른 캐릭터에 속한 대화나 버전은 거부한다.

보관함에는 대화 카드 하나만 표시한다. 카드에서 진입하면 마지막 선택 버전을 연다. 최근 메시지와 갱신 시각도 마지막 선택 버전을 기준으로 표시한다.

---
## 11. 내보내기와 가져오기

단일 대화 내보내기는 대화 공통 정보, 모든 버전, 모든 버전 메시지, 부모·자식 관계와 현재 선택 버전을 포함한다. 내보내기 형식 버전을 올려 기존 형식과 구분한다.

가져오기는 다음 조건을 검증한다.

- 모든 버전이 같은 대화에 소속
- 부모 버전과 분기 메시지 존재
- 원본 버전 하나 존재
- 순환 부모 관계 없음
- 같은 분기 지점의 버전 수가 10개 이하
- 메시지의 버전과 대화 연결 일치

검증 실패 시 기존 데이터를 변경하지 않는다. 다른 컴퓨터에서는 전체 데이터 또는 대화 파일을 가져와야 버전을 사용할 수 있다.

---
## 12. 컴포넌트 책임

- `ChatController`: 수정 요청 검증, AI 생성, 원자적 버전 생성, 중단과 실패 처리
- 버전 도메인 모듈: 버전 생성, 그룹 조회, 제한 검사, 삭제 범위 계산
- `app-reducer`: 버전 추가·선택·메시지 삭제·버전 삭제의 불변 상태 변경
- `MessageList`: 메시지 동작 메뉴와 버전 전환기 표시
- `ChatScreen`: 주소 동기화, 알림, 인라인 편집과 확인창 조정
- `LocalStorageGateway`: 스키마 6→7 마이그레이션과 검증
- 대화 내보내기 모듈: 전체 버전 왕복 직렬화
- 보관함: 마지막 선택 버전의 요약 표시

각 도메인 계산은 React 구성 요소와 분리해 단위 테스트할 수 있게 유지한다.

---
## 13. 오류 처리

- 빈 값·동일 값·길이 초과: 입력창 유지와 구체적 안내
- 토큰 부족: 생성 시작 전 중단
- 버전 10개 도달: 자동 삭제 없이 생성 거부
- AI 생성 실패·중단: 신규 버전과 토큰 변경 없음
- 저장 실패: 메모리 상태 반영 취소와 기존 저장값 유지
- 잘못된 주소: 마지막 선택 버전 또는 원본으로 안전 이동
- 클립보드 실패: 메시지 무변경과 접근 오류 안내
- 버전 삭제 실패: 현재 버전 유지와 백업 보존

---
## 14. 테스트 전략

---
### 14.1 단위 테스트

- 스키마 6→7 마이그레이션
- 기존 대화별 원본 버전 생성
- 수정 성공 시 독립 스냅샷 생성
- 생성 실패·중단·토큰 부족 시 원본 무변경
- 성공 시에만 1토큰 차감
- 분기 지점 최대 10개 제한
- 현재 버전 메시지 삭제의 격리
- 수정 버전과 하위 버전 연쇄 삭제
- 잘못된 부모 관계와 순환 가져오기 거부

---
### 14.2 통합 테스트

- 인라인 수정부터 버전 전환까지 전체 흐름
- 버전 전환 시 관계도·감정·장면 변경
- 버전 삭제 확인과 부모 버전 복귀
- 보관함에서 마지막 선택 버전 진입
- 전체 버전 내보내기·가져오기 왕복
- 새로고침 뒤 같은 버전 복원

---
### 14.3 브라우저 테스트

- 사용자 메시지 수정 후 `‹ 1 / 2 ›` 표시
- 원본과 수정본 왕복 전환
- 스트리밍 중 동작 비활성화
- 모바일 390픽셀 가로 넘침 없음
- 키보드만으로 수정·전환·삭제 수행
- 실패 시 토큰과 원본 대화 유지

---
## 15. 완료 조건

- 과거 사용자 메시지 수정 시 기존 대화가 보존됨
- 생성 성공 후 새 버전과 AI 답변이 함께 저장됨
- 메시지 아래 전환기로 모든 버전을 이동할 수 있음
- 각 버전의 메시지와 관계 상태가 서로 영향을 주지 않음
