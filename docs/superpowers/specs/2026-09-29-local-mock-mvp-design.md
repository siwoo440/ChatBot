# Local Mock MVP Design

---
## 1. 목적

외부 API, 계정, 결제, 서버 데이터베이스 없이도 핵심 채팅 흐름과 데이터 관리가 완결되는 로컬 Mock MVP를 만든다.

사용자는 캐릭터와 대화하고 메시지를 관리하며, 대화에서 생성된 요약과 기억을 조회·수정·삭제할 수 있어야 한다. 저장 실패나 잘못된 경로가 발생해도 기존 로컬 데이터를 자동 삭제하지 않고 안전하게 복구할 수 있어야 한다.

---
## 2. 현재 상태

현재 앱은 Next.js App Router, React Context, `useReducer`, `localStorage`, Mock LLM·이미지 어댑터로 구성되어 있다.

다음 기능은 이미 구현되어 있다.

- 캐릭터 탐색·상세·제작·수정·보관
- Mock 채팅과 스트리밍 응답
- 응답 중단·재시도·다시 생성
- 관계·감정·장면 상태 변경
- 로컬 데이터 내보내기·가져오기·백업·복구·초기화
- 설정과 대화 보관함

---
## 3. 1차 범위

1차 MVP에는 다음 기능을 포함한다.

- 메시지 복사·수정·개별 삭제
- 대화 요약과 캐릭터별 장기 기억
- 오류 경계·로딩·찾을 수 없음 화면
- 저장 실패와 데이터 손상 복구 안내
- 키보드·모바일·포커스 접근성 개선
- Playwright 핵심 흐름 E2E
- 설치·실행·데이터 관리 README

---
## 4. 제외 범위

다음 항목은 1차 MVP에 포함하지 않는다.

- 실제 LLM·이미지 생성 API
- 회원가입·로그인
- 서버 데이터베이스와 다중 기기 동기화
- 사용자 이미지 업로드
- 실제 결제
- 운영 배포와 외부 모니터링
- 검색·필터 고도화
- 캐릭터 편집기의 단계형 전환과 초안 자동 저장
- Text-Play 설치 파일과 코드 서명

검색·필터와 편집기 개선은 1.5차 사용성 개선으로 분리한다.

---
## 5. 개발 방식

각 기능을 데이터 구조, 도메인 로직, 화면, 자동 테스트까지 완결하는 수직 기능 단위로 구현한다.

개발 순서는 다음과 같다.

1. 오류 분류와 E2E 실행 기반
2. 메시지 관리
3. 장기 기억
4. 접근성과 반응형
5. 전체 E2E와 README

각 단위는 독립적으로 검증하고 커밋한다.

---
## 6. 아키텍처

기존 기술과 상태 경계를 유지한다.

- Next.js App Router와 React Context 유지
- `AppState`와 `app-reducer`를 전역 상태 기준으로 유지
- `LocalStorageGateway`를 영구 저장 경계로 유지
- `ChatController`가 전송·중단·재생성·메시지 변경을 조정
- `MockLLMAdapter`만 사용
- 신규 외부 라이브러리 추가 금지

메시지 변경과 기억 계산은 UI에서 분리한 순수 도메인 함수로 작성한다.

```text
MessageList
  └─ MessageActions
       └─ ChatController
            ├─ conversation-history
            ├─ conversation-memory
            └─ MockLLMAdapter
                 ↓
             AppState
                 ↓
        LocalStorageGateway
```

## 7. 메시지 관리

### 7.1 동작 범위

사용자 메시지는 복사·수정·삭제할 수 있다. AI 메시지는 복사·삭제할 수 있고, 마지막 AI 응답에는 다시 생성 기능을 유지한다.

스트리밍 중에는 수정·삭제를 비활성화한다.

### 7.2 수정 정책

사용자 메시지를 수정하면 해당 메시지 이후의 모든 메시지를 제거하고 수정된 내용으로 AI 응답을 다시 생성한다.

- 공백 입력 저장 금지
- 원문과 같은 내용 저장 금지
- 입력 길이는 기존 채팅 입력 제한과 동일
- 재생성 비용은 토큰 1개
- 토큰이 부족하면 수정도 적용하지 않음
- 재생성 실패 시 수정 전 상태 복구

### 7.3 삭제 정책

사용자 메시지를 삭제하면 해당 메시지와 이후 메시지를 함께 제거한다. AI 메시지는 선택한 응답만 제거한다.

마지막 AI 응답이 제거되어 대화가 사용자 메시지로 끝나면 다시 생성 버튼을 표시한다. 메시지 삭제로 토큰 사용량이나 이미 반영된 관계 수치는 되돌리지 않는다.

삭제 전에 현재 상태의 로컬 백업을 생성한다.

### 7.4 복사 정책

`navigator.clipboard.writeText()`를 사용한다. 성공하면 상태 메시지를 표시하고, 실패하면 데이터 변경 없이 클립보드 접근 오류를 표시한다.

## 8. 장기 기억

### 8.1 스키마

저장 스키마를 5에서 6으로 올리고 `AppState`에 기억 목록을 추가한다.

기억 항목은 다음 정보를 가진다.

- 기억 식별자
- 캐릭터 식별자
- 대화방 식별자
- 분류: `summary`, `event`, `preference`
- 내용
- 근거 메시지 식별자 목록
- 자동 생성 또는 사용자 수정 여부
- 생성·수정 시각

스키마 5 데이터는 빈 기억 목록이 포함된 스키마 6으로 자동 이전한다. 이전 전 원본을 복구 백업에 보존한다.

### 8.2 생성 규칙

- AI 응답이 정상 완료된 뒤에만 기억 갱신
- 중단·실패·빈 임시 응답 제외
- 새 메시지 12개마다 대화 요약 갱신
- `sceneEvent`가 있는 응답을 중요 사건으로 저장
- `기억해:`로 시작하는 사용자 내용을 선호 기억으로 저장
- 메시지 수정·삭제로 근거가 사라지면 연결된 자동 기억 제거
- 사용자가 수정한 기억은 자동 처리로 덮어쓰지 않음

기억 생성 실패는 정상 채팅, 토큰 차감, 관계 변화에 영향을 주지 않는다.

### 8.3 관리 화면

설정 화면에 `기억 관리` 탭을 추가한다.

화면은 캐릭터 선택, 대화 요약, 중요 사건, 사용자 선호 영역으로 구성한다.

- 대화 요약은 읽기 전용
- 중요 사건과 사용자 선호는 수정·삭제 가능
- 기억 삭제는 원본 채팅을 삭제하지 않음
- 빈 상태에서는 자동 생성 조건과 `기억해:` 사용법 안내

---
## 9. 화면 조작

데스크톱에서는 메시지에 마우스를 올리거나 키보드 포커스가 들어오면 동작 영역을 표시한다. 모바일에서는 메시지 메뉴 버튼을 항상 표시한다.

메시지 수정은 원래 메시지 위치의 인라인 편집창에서 진행한다.

- 기존 내용 자동 입력
- 저장·취소 제공
- `Escape`로 취소
- 완료 후 원래 메시지로 포커스 복귀
- 삭제 확인 화면에서 함께 제거되는 메시지 수 표시

상태 안내는 `role="status"`, 실패 안내는 `role="alert"`로 제공한다.

---
## 10. 오류 처리와 복구

오류는 입력 검증, 채팅 생성, 기억 생성, 저장공간, 데이터 손상, 페이지 오류로 구분한다.

다음 App Router 파일을 추가한다.

- `src/app/error.tsx`
- `src/app/loading.tsx`
- `src/app/not-found.tsx`

저장 실패 시 화면의 메모리 상태를 유지하고 자동 초기화하지 않는다. 사용자는 데이터를 JSON으로 내보내고, 저장공간을 정리한 뒤 다시 저장할 수 있어야 한다.

채팅 생성 실패 시 부분 응답을 유지하고 재시도를 제공한다. 기억 생성 실패 시 답변을 유지하고 기억 갱신만 이후 응답에서 재시도한다.

## 11. 접근성과 반응형

- 메시지 메뉴의 조작 영역 최소 높이 44px
- 대화상자 내부 포커스 고정
- 대화상자 종료 후 실행 버튼으로 포커스 복귀
- 모바일 인라인 편집창 전체 폭 사용
- 가상 키보드가 열린 상태에서도 저장·취소 접근 가능
- 모션 축소 환경에서 전환 애니메이션 제거
- 설정 탭 가로 스크롤과 선택 탭 자동 노출
- 390px, 820px, 1440px 화면에서 가로 넘침 금지

## 12. E2E 검증

Playwright Chromium에서 다음 흐름을 검증한다.

1. 홈에서 캐릭터 상세와 채팅으로 이동
2. 메시지 전송과 스트리밍 완료
3. 응답 중단과 다시 시도
4. 사용자 메시지 수정과 후속 응답 재생성
5. 사용자·AI 메시지 삭제
6. 기억 생성과 기억 관리 화면 확인
7. 기억 수정·삭제 후 새로고침 유지
8. 캐릭터 생성과 보관함 확인
9. 데이터 내보내기·초기화·복구
10. 존재하지 않는 주소와 캐릭터 오류 화면
11. 세 가지 기준 화면 너비의 가로 넘침 확인
12. 키보드만으로 메시지 메뉴와 대화상자 조작
