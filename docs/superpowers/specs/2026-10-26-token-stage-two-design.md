# 2단계 서버 토큰 관리와 채팅별 이용 내역

사용자 요청: 승인 대기 없이 가능한 2단계 개발, 이용 시각과 사용한 채팅방 표시, 검증 후 main 커밋·푸시.

---
## 설계 결정

- 기존 Next.js / TypeScript / Supabase REST 구조 유지, Native 실행. 새로운 결제·호스팅 연결 없음.
- 연습 모드는 기존 로컬 지갑 유지. 실제 계정은 별도 서버 지갑과 거래 원장이 권한 기준이며 로컬 백업·동기화의 지갑은 서버를 변경하지 못함.
- 기존 1,240 시험 토큰을 실제 계정에 자동 지급하지 않음. 서버 지갑 최초 잔액 0, 출석 등 검증된 보상으로 지급. 유료 토큰 전환 없음.
- 실제 계정의 지갑 변경 RPC는 서버 비밀 키 전용. 사용자 JWT는 서버에서 검증하고 본인 식별자를 결정. 브라우저에는 비밀 키 전달 금지.
- 실제 AI의 공개 요청은 서버 지갑 준비 없으면 차단. 로컬 연습 AI는 현재대로 이용 가능.
- 비용은 서버가 검증한 등급·길이·유저 노트로 계산. 요청 UUID와 내용 지문으로 중복·변조 요청 구분. 동시 요청은 DB 잠금과 음수 방지 제약으로 보호.
- 요청 전 예약 차감, 첫 유효 응답 직전 사용 확정. 응답 시작 전 실패·빈 답변·중단은 반환, 응답 시작 후 실패·중단은 사용 유지. 남은 예약은 10분 뒤 조회/요청 시 반환하며 늦은 응답 확정은 거부.
- 분·일·서비스 전체 사용량은 DB에 저장, 한국 날짜 기준. 실패한 요청도 요청 제한에는 포함하여 반복 호출 비용 방지. 보조 AI는 당일 완료된 대화당 두 번 및 서비스 전체 일일 대화 한도의 두 배까지만 허용. 독립적인 무료 반복 호출 차단(구현 중 비용 경로 검토에 따른 구현자 판단).
- 출석과 대화 횟수·새 대화 기반 미션만 서버 증거로 지급. 로컬 좋아요·이미지·초대 데이터만으로 실제 토큰 지급 금지. 이 항목은 서버 검증 가능한 데이터가 생길 때 연결.
- 사용 내역에는 한국 시간의 연·월·일·시·분·초, 사용 당시 채팅방 이름, 작품명, 비용, 잔액과 채팅방 이동 제공. 일반·스토리 경로 구분, 보관한 방은 명시적인 복구 후 연결. 이름 변경 뒤에도 당시 이름 보존. 삭제한 채팅방과 식별자가 없는 옛 기록은 이동 불가 안내.
- 기존 기록은 추측으로 채팅방에 연결하지 않음. 실제 계정 원장은 DB에서 보관, 화면은 최근 300건 제공와 범위 명시.

---
## 검토한 접근

1. 브라우저 차감 유지: 화면만 개선 가능하나 신뢰 가능한 잔액 불가.
2. 서버 메모리 지갑: 동시성 일부 해결, 재시작·다중 서버 문제 잔존.
3. DB 원장과 서버 API: 기존 계정 저장 구조 활용, 영속성과 원자성 확보. 이 방식 선택(구현자 판단).

---
## 검증과 한계

로컬 PostgreSQL 호환 실행기에서 실제 SQL·권한·중복·동시 요청·보상·반환을 검사. 서버 경로·클라이언트 연동 테스트와 브라우저 흐름 검증. 실제 외부 계정 설정은 현재 없어 원격 DB 적용·실계정·두 물리 PC 검증은 별도 확인 필요. 외부 DB와 실제 AI에 임의로 연결하지 않음.
