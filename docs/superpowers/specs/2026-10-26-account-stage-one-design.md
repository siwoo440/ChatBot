# 계정·데이터 안정화 1단계의 로컬 준비

목적은 실제 계정 검증에 들어가기 전에 이 컴퓨터에서 가능한 검사 안정화와 연결 점검 준비를 끝내는 것이다. 사용자는 추가 승인 없이 개발·검증·main 커밋·푸시를 요청했다.

---
## 범위와 접근

- 기존 Next.js, 계정 어댑터, 데이터 저장 구조를 유지한다.
- 영어 화면 검사는 모든 네트워크 요청의 종료 대신 화면의 복원·번역·화면 배치가 준비되었는지 확인한다. 기존 두 실패를 먼저 재현한다.
- `npm run check:account`는 환경 설정을 읽고 로그인 설정과 두 데이터 테이블의 익명 접근만 GET 요청으로 점검한다.
- 명령은 계정 생성, 이메일 발송, 로그인, 데이터 저장·삭제, SQL·RPC 실행을 하지 않는다.
- 키·비밀번호·프로젝트 주소·응답 본문·원시 오류를 출력하지 않는다. 공개 키만 허용하며 비밀 키와 service_role JWT는 요청 전에 거부한다.
- 연결 설정 누락은 실제 계정 미검증으로 명시하고 종료 코드 2를 반환한다. 읽기 점검 통과도 가입·로그인·RLS의 계정 간 분리 확인을 의미하지 않는다.
- HTTP는 로컬 테스트 서버에서만 허용하고, 원격 주소는 HTTPS만 허용한다. 리디렉션은 따라가지 않으며 요청 제한 시간을 둔다.
- README, HANDOFF, NEXT-SESSION, 계정 설정 문서에 실제 구현 범위와 다음 사용자 작업을 맞춘다.

고려한 방식은 검사 제한 시간만 늘리기, 화면 준비 상태 확인, 실제 서비스의 외부 설정까지 자동 변경하기다. 이번에는 원인을 직접 다루면서 외부 데이터 변경이 없는 화면 준비 상태 확인과 읽기 전용 점검을 채택했다.

---
## 완료 기준과 제한

- 기존 영어 화면 두 검사 및 전체 영어·반응형 검사 통과.
- 점검 도구의 설정 누락, 비밀 키 차단, 정상 권한 거절, 테이블 누락, 예상 밖 접근 허용, 서버 오류, 리디렉션, 시간 초과를 자동 검증.
- 기존 단위·통합 테스트, 타입, 린트, 프로덕션 빌드 통과.
- 실제 서비스 설정이 없는 이 환경에서는 실제 가입·두 기기 서버 복원·탈퇴 완료를 주장하지 않는다.
- 소스·문서만 커밋하고 환경 파일과 생성된 next-env.d.ts는 제외한다.
