# Character Detail Experience Design

---
## 1. 목적

현재의 단순한 캐릭터 상세 화면을 캐릭터 소개, 대화 시작 설정, 프롤로그 미리보기, 업데이트, 이용 지표, 연관 캐릭터를 한곳에서 확인할 수 있는 프리미엄 상세 경험으로 개편한다.

모든 캐릭터는 동일한 화면 구조를 사용하되 캐릭터별 이미지, 강조색, 설명, 시작 설정, 프롤로그를 데이터로 교체한다. 외부 서비스의 화면이나 자산을 복제하지 않고 참고 화면의 정보 계층만 활용해 Mate Verse 전용 시각 체계를 만든다.

---
## 2. 사용자 목표

사용자는 상세 페이지에서 다음 질문에 바로 답을 얻을 수 있어야 한다.

- 어떤 캐릭터인가
- 어떤 분위기와 세계관인가
- 어떤 콘텐츠가 포함되는가
- 어떤 관계와 상황으로 대화를 시작하는가
- 기존 대화를 이어갈지 새 회차를 시작할지
- 비슷한 캐릭터는 무엇인가

---
## 3. 범위

포함 범위는 다음과 같다.

- 캐릭터 히어로와 제작자 정보
- 태그·배지·콘텐츠 등급·주의 사항
- 상세 설명과 설정 정보
- 대화 프로필과 시작 프리셋
- 프롤로그 장면과 첫 대사
- 기존 대화 이어하기와 새 회차 시작
- 로컬 업데이트 이력
- Mock 이용 지표와 샘플 랭킹
- 태그 기반 연관 캐릭터
- 보관·공유·신고 메뉴의 로컬 동작
- 반응형·키보드·스크린리더 지원
- 캐릭터별 프롤로그 이미지 생성

---
## 4. 제외 범위

- 실제 사용자 좋아요·조회·댓글 집계
- 실제 제작자 팔로우 서버
- 신고 운영자 검수
- 서버 기반 개인화 추천
- 다중 기기 대화 동기화
- 결제 또는 유료 캐릭터 잠금

서버 데이터가 필요한 영역은 Mock 또는 로컬 상태임을 화면에 명확히 표시한다.

---
## 5. 시각 방향

전체 화면은 짙은 남청색 배경과 저채도 패널을 사용한다. 캐릭터별 강조색은 CSS 변수로 주입한다.

- 기본 배경: `#070910`
- 패널 배경: `#11141d`
- 보조 패널: `#171b26`
- 기본 본문: `#f5f7fb`
- 보조 본문: `#a8b0c0`
- 경계선: `rgba(255, 255, 255, 0.1)`
- 캐릭터 강조색: 데이터 기반 CSS 변수

대표 이미지의 색상을 흐리게 확장한 배경 레이어와 부드러운 그라디언트를 사용한다. 배경 효과는 기존 대표 이미지와 CSS로 만들고 별도 생성 이미지를 사용하지 않는다.

모서리는 16px에서 24px 사이로 통일하고 버튼, 배지, 패널의 표면 깊이를 명확히 구분한다. 장식보다 캐릭터 이미지와 텍스트 계층을 우선한다.

---
## 6. 페이지 구조

```text
CharacterDetail
├─ CharacterHero
│  ├─ CharacterPortrait
│  ├─ CreatorSummary
│  ├─ CharacterBadges
│  ├─ CharacterMetrics
│  └─ CharacterQuickActions
├─ CharacterStoryInfo
├─ ConversationSetup
├─ ProloguePreview
├─ CharacterUpdateHistory
├─ CharacterRanking
├─ RelatedCharacterRail
└─ CharacterActionBar
```

`CharacterDetail`은 상태 연결과 섹션 조합만 담당한다. 각 하위 컴포넌트는 자신의 표시와 상호작용만 관리한다.

---
## 7. 히어로 영역

데스크톱에서는 대표 이미지와 정보 영역을 420px 대 나머지 공간의 두 열로 배치한다. 모바일에서는 대표 이미지를 상단 전체 폭으로 배치하고 정보 영역을 아래에 쌓는다.

표시 정보는 다음과 같다.

- 제작자 이름
- 캐릭터 이름
- 한 줄 소개
- 캐릭터 배지
- 콘텐츠 등급
- 태그
- 대화 수·보관 수·평가 수
- 좋아요·보관·공유·더보기

Mock 지표에는 `샘플 데이터` 표시를 제공한다. 실제 서비스처럼 오인할 수 있는 실시간 표현은 사용하지 않는다.

---
## 8. 상세 설명

상세 설명 영역은 다음 항목을 순서대로 표시한다.

- 캐릭터 소개
- 성격
- 세계관
- 관계 설정
- 대화 스타일
- 콘텐츠 주의 사항

내용이 긴 경우 처음에는 제한된 높이만 표시하고 `전체 보기`로 확장한다. 줄바꿈을 보존하되 HTML 문자열을 직접 렌더링하지 않는다.

---
## 9. 대화 시작 설정

새 회차를 시작하기 전에 다음 값을 선택할 수 있다.

- 사용자 대화 프로필
- 시작 관계
- 시작 상황
- 대화 분위기

기존 대화의 `이어하기`는 저장된 값을 그대로 사용한다. 새 회차의 `새 대화 시작`에서만 설정을 변경할 수 있다.

시작 프리셋에는 식별자, 이름, 설명, 초기 관계, 초기 감정, 첫 장면, 첫 대사가 포함된다.

---
## 10. 여러 대화 회차

캐릭터당 하나의 대화만 재사용하는 현재 제약을 제거한다.

- `이어하기`: 가장 최근 활성 대화로 이동
- `새 대화 시작`: 선택한 프리셋으로 새 대화 생성
- 기존 대화는 삭제하지 않고 보관함에 유지
- 새 대화 식별자는 충돌하지 않는 고유값 사용
- 시작 설정은 대화방에 저장
- 보관함에서 캐릭터별 여러 회차 구분

새 회차 생성은 토큰을 사용하지 않는다. 첫 사용자 메시지부터 기존 채팅 토큰 정책을 적용한다.

---
## 11. 프롤로그 미리보기

프롤로그 영역은 다음 요소로 구성한다.

- 프롤로그 제목
- 시작 상황 설명
- 가로형 장면 이미지
- 캐릭터 첫 대사
- 선택한 시작 프리셋 이름

프리셋이 바뀌면 설명, 장면, 첫 대사를 함께 변경한다. 이미지 로딩 실패 시 대표 이미지와 캐릭터 강조색을 이용한 대체 화면을 표시한다.

---
## 12. 업데이트·랭킹·연관 캐릭터

업데이트 이력은 버전, 날짜, 제목, 변경 항목을 가진 로컬 정적 데이터로 제공한다.

랭킹은 주간·일간·누적 탭을 제공하되 `샘플 랭킹`으로 표시한다. 로컬 Mock 프로필의 순위도 샘플 데이터임을 명시한다.

연관 캐릭터는 태그 일치 수, 세계관 키워드, 공개 상태를 이용해 계산한다. 같은 캐릭터는 제외하고 최대 8개를 표시한다.

---
## 13. 하단 동작 영역

모바일과 좁은 화면에서는 하단 고정 동작 영역을 사용한다.

- 활성 대화가 있을 때 `이어하기`
- 항상 `새 대화 시작`
- 데스크톱에서는 히어로와 페이지 하단에 같은 주요 동작 제공
- 가상 키보드 또는 모바일 하단 메뉴와 겹치지 않도록 안전 영역 반영

---
## 14. 로컬 상호작용

- 보관: 기존 `bookmarkedCharacterIds` 사용
- 좋아요: 로컬 사용자 반응 상태 추가
- 공유: 현재 상세 URL 클립보드 복사
- 신고: 사유를 선택해 로컬 신고 기록에 저장하고 Mock임을 표시
- 제작자 팔로우: 로컬 팔로우 상태로 제공하고 서버 동기화 없음 표시

좋아요·팔로우·신고는 외부 요청을 보내지 않는다.

---
## 15. 데이터 구조

기존 `Character`의 핵심 창작 정보는 유지하고 상세 표시 전용 구조를 추가한다.

```text
CharacterDetailProfile
├─ characterId
├─ accentColor
├─ badges
├─ contentRating
├─ contentWarnings
├─ dialogueStyle
├─ relationshipSetup
├─ startPresets
├─ prologues
├─ releaseNotes
├─ sampleMetrics
└─ relatedCharacterIds
```

대화방에는 시작 프리셋 식별자, 사용자 프로필 식별자, 시작 시점의 설정을 저장한다. 나중에 캐릭터 기본값이 바뀌어도 기존 대화의 시작 조건은 변경하지 않는다.

상세 프로필이 없는 랭킹 캐릭터는 기존 `Character` 정보로 기본 상세 프로필을 계산한다.

### 15.1 저장 스키마 조정

이 기능과 Local Mock MVP는 하나의 스키마 5에서 6으로의 이전을 공유한다. 별도의 스키마 번호를 각각 만들지 않는다.

스키마 6 이전에서 기억 목록, 캐릭터별 로컬 반응 상태, 제작자 팔로우 상태, 로컬 신고 기록, 대화 시작 설정을 함께 기본값으로 추가한다. 캐릭터 상세 기능을 먼저 구현할 때도 빈 기억 목록을 포함하고, 이후 장기 기억 기능은 같은 필드를 사용한다.

---
## 16. 생성 이미지 전략

이미지 생성은 래스터 장면 자산에만 사용한다. 버튼 아이콘, 등급 배지, 화살표, 메뉴 아이콘은 인라인 SVG 또는 CSS로 작성한다.

1차 이미지 생성 대상은 주요 캐릭터 7명이다.

- `rian`
- `harin`
- `sera`
- `kyle`
- `noah`
- `miel`
- `yuna`

각 캐릭터의 기존 대표 이미지를 정체성 기준 이미지로 사용해 가로형 프롤로그 장면 한 장을 생성한다.

저장 위치:

`public/images/characters/prologues/<character-id>-prologue-v1.png`

공통 생성 지침:

```text
Use case: identity-preserve
Asset type: character story prologue scene for a web detail page
Input images: Image 1: existing character portrait used only as the identity and style reference
Primary request: place the same character in the opening scene described by the character world setting
Style/medium: preserve the existing illustration style and rendering quality
Composition/framing: cinematic landscape composition, character clearly visible, safe center crop for desktop and mobile
Constraints: preserve face, hair, outfit identity, proportions, palette, and personality; original scene; no text; no logos; no watermark
Avoid: UI elements, speech bubbles, captions, extra foreground characters, distorted hands, cropped face
```

각 캐릭터의 세계관, 시간대, 감정, 행동만 개별 프롬프트에서 변경한다. 결과는 원본 크기로 검토한 뒤 저장소로 복사하고 코드에서 해당 저장소 경로만 사용한다.

---
## 17. 접근성

- 모든 동작 버튼에 대상이 포함된 접근성 이름 제공
- 대표 이미지와 프롤로그에 의미 있는 대체 텍스트 제공
- 배지 색상만으로 상태를 구분하지 않음
- 선택 프리셋에 `aria-current` 또는 `aria-selected` 제공
- 탭 키로 모든 동작 접근 가능
- 포커스 표시 대비 3:1 이상
- 본문과 배경 텍스트 대비 4.5:1 이상
- 모션 축소 설정에서 배경 이동과 전환 제거
- 하단 고정 영역이 본문을 가리지 않도록 여백 확보

---
## 18. 성능

- 대표 이미지는 첫 화면 우선 로딩
- 프롤로그와 연관 캐릭터 이미지는 지연 로딩
- `next/image`의 반응형 `sizes` 지정
- 가로형 생성 이미지는 화면 크기에 맞는 변형 제공
- CSS 배경 흐림 효과는 단일 레이어로 제한
- 화면 밖 랭킹과 연관 캐릭터는 불필요한 상태 갱신 금지

---
## 19. 오류 처리

- 캐릭터 없음: 전용 빈 상태와 탐색 이동
- 상세 프로필 없음: 기본 프로필 계산
- 프롤로그 이미지 없음: 대표 이미지 기반 대체 화면
- 클립보드 실패: 공유 실패 안내
- 새 회차 생성 실패: 기존 대화와 선택 상태 유지
- 로컬 저장 실패: 인메모리 상태 유지와 데이터 내보내기 안내

---
## 20. 테스트

단위 테스트:

- 기본 상세 프로필 계산
- 연관 캐릭터 점수와 자기 자신 제외
- 최신 활성 대화 선택
- 새 회차 고유 식별자 생성
- 시작 프리셋의 대화 상태 변환

통합 테스트:

- 상세 정보와 콘텐츠 경고 표시
- 보관·좋아요·공유 상태
- 프리셋 선택에 따른 프롤로그 변경
- 이어하기와 새 회차 생성
- 여러 회차가 보관함에 유지되는지 확인
- 상세 프로필이 없는 캐릭터의 기본 화면

E2E 테스트:

- 홈에서 캐릭터 상세 진입
- 시작 프리셋 선택과 새 대화 시작
- 상세 페이지 복귀 후 최근 대화 이어하기
- 모바일 하단 동작 영역
- 키보드만으로 핵심 동작 수행
- Mock 모드에서 외부 요청 없음

---
## 21. 구현 순서

1. 상세 데이터 구조와 기본 프로필 계산
2. 히어로·상세 설명과 전용 CSS
3. 시작 프리셋·프롤로그·여러 회차
4. 업데이트·샘플 랭킹·연관 캐릭터
5. 로컬 반응·공유·신고
6. 주요 캐릭터 프롤로그 이미지 생성과 연결
7. 접근성·반응형·전체 테스트

---
## 22. 완료 기준

- 모든 공개 캐릭터 상세 페이지가 동일한 구조로 표시됨
- 주요 캐릭터 7명의 원본 프롤로그 이미지 연결
- 기존 대화 이어하기와 새 회차 생성 분리
- 새 회차 생성 시 기존 대화 손실 없음
- Mock 통계와 실제 통계가 혼동되지 않음
- 모바일·태블릿·데스크톱 가로 넘침 없음
- 키보드 핵심 흐름 완료 가능
- 외부 네트워크 요청 없음
- ESLint, TypeScript, Vitest, Playwright, 프로덕션 빌드 통과
