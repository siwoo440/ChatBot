# 로그인과 서버 저장 연결하기 (Supabase, Google 로그인)

이 문서는 Mate Verse ChatBot에 실제 로그인과 서버 저장을 연결하는 순서를 적는다. 가입과 값 입력은 프로젝트 주인이 직접 한다. 여기 나오는 서비스는 모두 무료 요금제로 시작할 수 있다.

- **연결만 해 두고 쓰지 않을 수 있다.** 2~3단계까지 해 두어도 5단계의 스위치를 켜기 전에는 앱이 지금처럼 연습용 로그인으로 동작한다.
- **비밀 값은 대화나 문서에 적지 않는다.** 값은 `.env.local`과 Supabase·Google 화면에만 넣는다.
- 준비물: Supabase 계정, Google 계정(Google 로그인을 쓸 때).
- 서비스 화면의 메뉴 이름은 서비스가 바꾸면 조금 다를 수 있다. 찾지 못하면 비슷한 이름을 찾거나 물어본다.

## 한눈에 보기

| 순서 | 어디서 | 무엇을 | 걸리는 시간 |
| --- | --- | --- | --- |
| 1 | Supabase | 프로젝트 만들기 | 5분 |
| 2 | Supabase | 데이터베이스 설정 실행(`supabase/account-setup.sql`) | 2분 |
| 3 | 내 컴퓨터 | `.env.local`에 주소와 공개 키 넣기 | 2분 |
| 4 | Google Cloud, Supabase | Google 로그인 켜기(선택) | 15분 |
| 5 | 내 컴퓨터 | 스위치 켜기(쓰기 시작할 때) | 1분 |
| 6 | 브라우저 | 확인하기 | 5분 |

## 1. Supabase 프로젝트 만들기

1. <https://supabase.com/dashboard> 에 로그인한다.
2. `New project`를 누른다.
3. 이름은 알아보기 쉽게 정한다(예: `mateverse-chatbot`). 지역(Region)은 `Northeast Asia (Seoul)`을 고른다.
4. 데이터베이스 비밀번호는 화면이 만들어 주는 것을 쓰고, 안전한 곳에 따로 적어 둔다. 이 비밀번호는 앱에 넣지 않는다.
5. 요금제는 Free를 고르고 만든다. 준비가 끝날 때까지 1~2분 기다린다.

홈페이지에서 쓰는 프로젝트와 따로 만들기를 권한다. 대화 데이터는 양이 많고 성인 내용이 섞일 수 있어 나눠 두는 편이 안전하다. 무료 요금제에서 만들 수 있는 프로젝트 수는 Supabase 화면의 안내를 따른다.

## 2. 데이터베이스 설정 실행

1. Supabase 프로젝트 화면 왼쪽에서 `SQL Editor`를 연다.
2. 저장소의 `supabase/account-setup.sql` 파일을 열어 내용을 모두 복사한다.
3. SQL Editor에 붙여 넣고 `Run`을 누른다. `Success`가 나오면 된다.
4. 왼쪽 `Table Editor`에서 `mv_snapshots`와 `mv_blobs` 두 표가 생겼는지 본다.

이 설정이 하는 일: 계정마다 앱 데이터 한 벌을 두는 표를 만들고, 로그인한 사람이 **자기 줄만** 읽고 쓸 수 있게 막는다. 여러 번 실행해도 같은 결과가 된다.

계정 지우기(탈퇴)에 쓰는 함수 `mv_delete_account`도 이 파일이 만든다. 로그인한 사람이 부르면 **자기 계정만** 지우고, 그 계정의 저장본도 함께 지워진다. 2026-10-07 전에 이 파일을 실행했다면 **한 번 더 실행**해야 탈퇴가 동작한다(다시 실행해도 저장된 데이터는 그대로다).

## 3. `.env.local`에 주소와 공개 키 넣기

1. Supabase 프로젝트 화면에서 `Project Settings → API Keys`를 연다(주소는 `Project Settings → API` 또는 `Data API`에 있다).
2. 다음 두 값을 찾는다.
   - **Project URL**: `https://`로 시작하고 `.supabase.co`로 끝나는 주소. 화면이 끝에 `/rest/v1/`을 붙여 보여 주면 그대로 복사해도 된다(앱이 떼고 쓴다)
   - **공개 키**: `Publishable key`(`sb_publishable_`로 시작). 예전 방식의 프로젝트라면 `anon` `public`이라고 적힌 키
3. ChatBot 폴더의 `.env.local` 파일을 메모장으로 열어 아래 세 줄을 넣는다(없으면 `.env.example`에서 복사한다).

```text
NEXT_PUBLIC_ACCOUNT_SERVICE=practice
NEXT_PUBLIC_SUPABASE_URL=여기에 Project URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=여기에 공개 키
```

주의할 점:

- **`Secret key`(`sb_secret_`로 시작)나 `service_role` 키는 절대 넣지 않는다.** 이 세 값은 브라우저에 그대로 나가는 값이라, 공개해도 되는 키만 넣어야 한다. 비밀 키를 넣으면 누구나 모든 데이터를 읽고 지울 수 있게 된다.
- 값 앞뒤에 따옴표나 빈칸을 넣지 않는다. 주소 끝에는 화면이 붙여 주는 `/rest/v1/` 말고 다른 경로를 붙이지 않는다.
- 같은 이름의 줄을 두 번 적지 않는다. 두 번 있으면 아래쪽 줄이 적용된다.
- `여기에 Project URL` 같은 안내문 글자를 그대로 두지 않는다. 주소나 키가 올바른 모양이 아니면 스위치를 켜도 연습용으로 동작한다.
- `NEXT_PUBLIC_ACCOUNT_SERVICE`가 `practice`인 동안에는 값을 넣어 두어도 앱이 쓰지 않는다.

### 메일의 링크가 돌아올 주소 넣기

앱이 보내게 하는 메일은 두 가지다. 가입 확인 메일의 링크는 앱의 `/auth/callback` 화면으로 돌아와 바로 로그인되고, 로그인 화면의 `비밀번호를 잊으셨나요?`가 보내는 메일의 링크는 `/auth/reset` 화면으로 돌아와 새 비밀번호를 정한다. Supabase는 미리 적어 둔 주소로만 돌려보낸다.

1. Supabase 프로젝트 화면에서 `Authentication → URL Configuration`을 연다.
2. **`Site URL`에 개발 서버 주소를 넣는다**(예: `http://localhost:3002`). 이것은 꼭 한다. 처음 값은 `http://localhost:3000`이라, 다른 포트를 쓰면 메일의 링크가 열리지 않는 주소로 간다.
3. `Redirect URLs`에 `http://localhost:3002/auth/callback`과 `http://localhost:3002/auth/reset`을 추가한다(다른 포트를 쓰면 그 포트로. 여러 개 넣어도 된다). 권장이다.

3번을 넣지 않으면 메일의 링크가 `Site URL`(앱의 메인 화면)로 돌아오는데, 앱이 링크의 종류를 보고 맞는 화면으로 다시 보내 준다. 그래서 2번만 맞으면 동작한다.

## 4. Google 로그인 켜기 (선택)

이메일 로그인만 쓸 거라면 건너뛴다.

### 4-1. Supabase에서 돌아올 주소 확인

1. Supabase 프로젝트 화면에서 `Authentication → Sign In / Providers → Google`을 연다.
2. `Callback URL (for OAuth)`에 적힌 주소를 복사해 둔다. `https://<프로젝트>.supabase.co/auth/v1/callback` 모양이다.

### 4-2. Google Cloud에서 로그인 설정

1. <https://console.cloud.google.com> 에 로그인하고, 홈페이지 때 만든 프로젝트를 고르거나 새로 만든다.
2. `API 및 서비스 → OAuth 동의 화면`이 아직 없으면 만든다(앱 이름, 지원 이메일). 사용자 유형은 `외부`다.
3. `API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID`를 고른다.
4. 애플리케이션 유형은 `웹 애플리케이션`이다.
5. `승인된 리디렉션 URI`에 4-1에서 복사한 Supabase 주소를 넣는다.
6. 만들면 나오는 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 복사한다.

동의 화면이 `테스트` 상태인 동안에는 `테스트 사용자`에 넣은 Google 계정만 로그인할 수 있다. 혼자 시험할 때는 내 계정만 넣어 두면 된다. 다른 사람에게 열 때 `게시`한다.

### 4-3. Supabase에 넣기

1. 4-1의 Google 화면으로 돌아가 `Enable Sign in with Google`을 켠다.
2. `Client ID`와 `Client Secret`에 4-2의 값을 넣고 저장한다. 이 두 값은 Supabase 화면에만 넣는다(`.env.local`에는 넣지 않는다).
3. `Authentication → URL Configuration`을 연다.
   - `Site URL`: 개발 서버 주소(예: `http://localhost:3002`)
   - `Redirect URLs`에 추가: `http://localhost:3002/auth/callback` (다른 포트를 쓰면 그 포트로. 여러 개 넣어도 된다)

## 5. 스위치 켜기 (쓰기 시작할 때)

실제 로그인을 쓰기로 했을 때 `.env.local`의 한 줄만 바꾼다.

```text
NEXT_PUBLIC_ACCOUNT_SERVICE=supabase
```

바꾼 뒤에는 개발 서버를 껐다가 다시 켠다(이 값들은 서버를 켤 때 읽는다). 다시 연습용으로 돌리려면 `practice`로 바꾸고 서버를 다시 켠다.

- 스위치를 바꾸면 그 전 방식으로 로그인해 둔 계정은 로그인하지 않은 것으로 본다. 데이터는 지워지지 않고, 그 방식으로 돌아가 로그인하면 다시 보인다.
- 연습용 계정에 있던 데이터를 실제 계정으로 옮기려면 연습용일 때 `개인정보 및 보안 → 데이터 관리`에서 JSON으로 내보내고, 실제 계정으로 로그인한 뒤 가져온다.
- 화면 테스트(E2E)는 스위치와 상관없이 연습용으로 돈다(`playwright.config.ts`가 테스트 서버를 연습용으로 띄운다). 테스트가 실제 서비스에 가입하는 일은 없다. 프로덕션 빌드로 테스트할 때는 빌드할 때 `NEXT_PUBLIC_ACCOUNT_SERVICE=practice`를 준다(`HANDOFF.md` 4절).

## 6. 확인하기

1. `http://localhost:3002/login`을 연다. 이름 입력 대신 **이메일과 비밀번호** 칸이 보이면 스위치가 켜진 것이다.
2. `회원가입`으로 바꿔 내 이메일로 가입한다. 확인 메일이 오면 메일의 버튼을 누른다. 앱이 열리면서 **바로 로그인된다**(가입한 브라우저가 아니어도 된다). `로그인하지 못했어요`와 함께 링크가 만료됐다는 안내가 나오면, 확인은 이미 됐을 수 있으니 로그인 화면에서 이메일과 비밀번호로 로그인해 본다.
3. 로그인하면 오른쪽 사용자 패널에 계정 이름과 `서버에 저장됨`이 보인다.
4. Supabase의 `Table Editor → mv_snapshots`에 줄이 하나, `mv_blobs`에 줄이 여러 개(앱 데이터를 나눈 조각) 생겼는지 본다.
5. 다른 브라우저(또는 시크릿 창)에서 같은 계정으로 로그인해, 앞에서 바꾼 내용(예: 보관한 캐릭터)이 그대로 보이는지 확인한다.
6. Google 로그인을 켰다면 `Google로 계속하기` 버튼이 보인다. 눌러서 로그인되는지 확인한다.
7. 탈퇴까지 확인하려면 시험용으로 만든 계정으로 로그인해 `개인정보 및 보안 → 계정 관리 → 계정 지우기(탈퇴)`를 누른다. 손님 화면으로 돌아오면 Supabase의 `Authentication → Users`에서 그 계정이, `Table Editor → mv_snapshots`에서 그 줄이 사라졌는지 본다. 되돌릴 수 없으니 쓰던 계정으로 하지 않는다.
8. 비밀번호 다시 정하기를 확인하려면 로그아웃한 뒤 로그인 화면에서 `비밀번호를 잊으셨나요?`를 누르고 가입한 이메일을 적어 `재설정 메일 보내기`를 누른다. 받은 메일의 링크를 누르면 `비밀번호 다시 정하기` 화면이 열린다. 새 비밀번호를 두 번 적고 `비밀번호 바꾸기`를 누르면 바로 로그인된다. 로그아웃한 뒤 새 비밀번호로 다시 로그인되는지도 본다.

## 밖에서 점검하기 (값을 내보내지 않고)

가입하지 않고도 연결이 어디까지 됐는지 볼 수 있다. `.env.local`의 주소와 공개 키를 읽어 **읽기만 하는 요청** 세 가지를 보낸다(머리말: `apikey`와 `authorization: Bearer`에 공개 키). 점검 도구는 값을 화면에 내보내지 않고 모양(길이, 시작 글자, 경로)과 응답만 내보낸다.

| 요청 | 정상일 때 | 뜻 |
| --- | --- | --- |
| `GET /auth/v1/settings` | 200. `external.email`이 `true` | 주소와 공개 키가 맞다. `external.google`로 Google 로그인이 켜졌는지, `mailer_autoconfirm`으로 확인 메일이 필요한지도 본다 |
| `GET /rest/v1/mv_snapshots?select=user_id&limit=1` | 401, 코드 `42501`(`permission denied`) | 표가 있고, 로그인하지 않으면 읽지 못한다. 404(`PGRST205`)면 2단계의 SQL을 실행하지 않은 것 |
| `GET /rest/v1/mv_blobs?select=hash&limit=1` | 401, 코드 `42501`(`permission denied`) | 조각 표가 있고, 로그인하지 않으면 읽지 못한다. 404(`PGRST205`)면 SQL을 가장 최근 파일로 다시 실행해야 한다 |
| `GET /auth/v1/authorize?provider=google&redirect_to=…`(따라가지 않음) | 302로 `accounts.google.com`에 넘어가고 `redirect_uri`가 `<프로젝트 주소>/auth/v1/callback` | Google 로그인이 켜져 있다. 400(`provider is not enabled`)이면 꺼져 있는 것 |

`Redirect URLs`에 넣은 돌아올 주소는 밖에서 볼 수 없다. 실제로 Google 로그인을 해 봐야 안다.

## 안 될 때

| 보이는 것 | 확인할 것 |
| --- | --- |
| 로그인 화면이 여전히 이름만 묻는다 | `.env.local`의 세 값이 모두 있는지, 주소 칸에 안내문 글자가 남아 있지 않은지, 스위치 줄이 두 번 있지 않은지(아래쪽 줄이 적용됨), 스위치가 `supabase`인지, 서버를 다시 켰는지 |
| `지금은 로그인할 수 없어요` | Project URL이 맞는지, 공개 키가 맞는지, 인터넷 연결 |
| `받은 메일의 확인 버튼을 누른 뒤 로그인해 주세요` | 메일함(스팸함 포함). Supabase 기본 메일은 한 시간에 보낼 수 있는 수가 적다 |
| 사용자 패널에 `서버에 저장하지 못했어요` | 2단계의 SQL을 **가장 최근 파일로** 실행했는지(`mv_snapshots`와 `mv_blobs` 두 표가 모두 있는지). 표를 더한 뒤에 받은 코드라면 SQL을 한 번 더 실행한다 |
| 화면 아래에 `로그인이 끝났어요` 안내 | 다른 기기에서 로그아웃했거나 오래 쓰지 않아 로그인이 끝난 것이다. `다시 로그인`을 눌러 같은 계정으로 로그인하면 이 기기의 데이터로 이어서 쓴다 |
| 탈퇴할 때 `계정을 지우지 못했어요` | 2단계의 SQL을 최신 파일로 다시 실행했는지(`mv_delete_account` 함수가 있어야 한다. Supabase 화면의 `Database → Functions`에서 볼 수 있다) |
| 메일의 링크를 눌렀는데 열리지 않거나 다른 사이트가 열린다 | `Authentication → URL Configuration`의 `Site URL`이 지금 쓰는 개발 서버 주소인지(3단계 아래의 「메일의 링크가 돌아올 주소 넣기」) |
| 메일의 링크를 눌렀는데 `링크가 만료됐거나 이미 사용됐어요` | 링크는 한 번만 쓸 수 있다. 가입 확인이었다면 이미 확인됐을 수 있으니 로그인해 본다. 안 되면 같은 이메일로 다시 가입해 메일을 새로 받는다 |
| `링크가 만료됐거나 이미 사용됐어요` | 링크는 한 번만 쓸 수 있고 시간이 지나면 끝난다. 로그인 화면에서 메일을 다시 받는다. 메일 프로그램이 링크를 미리 열어 보는 경우에도 이렇게 될 수 있다 |
| `요청이 너무 잦아요` | Supabase 기본 메일은 한 시간에 보낼 수 있는 수가 적다. 잠시 뒤 다시 한다 |
| Google 버튼이 없다 | 4-3에서 Google을 켜고 저장했는지 |
| Google 로그인 뒤 `로그인하지 못했어요` | `Redirect URLs`에 `http://localhost:포트/auth/callback`이 있는지, Google의 `승인된 리디렉션 URI`가 Supabase 주소인지, 테스트 사용자에 내 계정이 있는지 |

## 알아 둘 것

- 이 연결 코드는 가짜 서버로 시험했다. 실제 프로젝트로는 2026-10-06에 **읽기만 하는 요청 세 가지**만 확인했다: 로그인 설정이 읽히는지(`/auth/v1/settings`), `mv_snapshots` 표가 있고 공개 키만으로는 읽을 수 없는지(`permission denied`가 나오면 정상), Google 로그인이 켜져 있는지. 같은 날 스위치를 켜고 로그인 화면이 이메일·비밀번호와 회원가입으로 바뀌는 것, 브라우저에서 보낸 설정 요청이 성공하는 것까지 봤다. **가입, 로그인, 서버 저장, Google 로그인은 아직 실제로 돌려 보지 않았으므로** 6단계를 꼭 해 본다.
- 계정 지우기(탈퇴)도 가짜 서버와 내 컴퓨터의 시험용 데이터베이스로만 확인했다(자기 계정만 지워지는지, 로그인하지 않으면 부르지 못하는지 등). **실제 프로젝트에서는 아직 돌려 보지 않았다.** 6단계의 7번으로 처음 확인한다.
- 「이 기기에서 계정 데이터 지우기」는 이 브라우저에 있는 계정 데이터만 지우고 로그아웃한다. 서버의 저장본은 그대로라 다시 로그인하면 받아 온다.
- 무료 요금제의 프로젝트는 한동안 쓰지 않으면 멈출 수 있다. 멈췄으면 Supabase 화면에서 다시 켠다.
- 비밀번호 다시 정하기(메일 요청, 메일의 링크로 들어와 새 비밀번호 정하기)도 가짜 서버로만 확인했다. **실제 프로젝트에서는 아직 돌려 보지 않았다.** 6단계의 8번으로 처음 확인한다. 메일의 링크는 주소 뒤에 출입증을 붙여 돌아오고, 앱은 그 값을 읽자마자 주소 칸에서 지운다.
- 앱 데이터는 조각으로 나눠 `mv_blobs`에 두고, 조각 목록 한 줄을 `mv_snapshots`에 둔다(바뀐 조각만 올리고 받는다. `HANDOFF.md` 43절). 토큰 잔액도 그 안에 있어 브라우저가 정한 값을 그대로 믿는다. 다른 사람에게 열기 전에 바꿔야 한다.
- 다른 사람에게 여는 일(공개 주소, 개인정보처리방침, 이용약관)은 이 문서의 범위가 아니다.
